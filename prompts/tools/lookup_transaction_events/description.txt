工具：lookup_transaction_events

用途：按链和交易哈希，定位当前已索引数据中的相关事件，返回有限事件引用及实际数据来源范围。

适用：用户给出交易哈希，想了解相关事件、参与对象，或为前后行为分析先定位交易。
不适用：完整交易调用树、执行成功/失败判定、未采集代币的完整资金路径、全链搜索；这些需要额外能力和证据。

参数语义：chain_id 与 tx_hash 用于定位。token_address 只在需要限定代币时提供，不强制用户补填。page_size 限制单页数量，cursor 仅续取服务端此前返回且属于相同查询的游标。交易查询不要求独立时间参数。
字段类型和必填性以该工具的 Pydantic 输入模型为唯一来源，不在此另写 JSON Schema。

结果使用：同一交易的多条日志不是多笔交易。当前数据未找到不能写成“链上交易不存在”或“交易失败”。事件只能支持实际已索引范围内的描述，不能推断完整交易。需要研究前后变化时，再选择时段分析工具。
状态处理：success 可包含真实空结果；partial 必须保留限制；failed、unsupported、needs_input、cancelled 不可解释为零条成功结果。

执行内容：返回正式 Transfer 和已补齐 Swap 的分页明细、事件引用、方法版本与数据截止。只在授权数据集中查询；未指定代币且授权范围不唯一时，需要先明确代币。Swap 独立水位落后时明确标记 partial；区块哈希缓存缺失可为 null。游标绑定用户、研究修订、筛选及快照，过期或快照变化须重新查询。

示例意图：“这笔交易中 BEM 发生了什么？”——定位用户明确的交易哈希，按实际采集范围返回事件证据，不凭哈希长度猜测是交易还是区块。
