工具：analyze_token_activity

用途：围绕代币在重点时段的活动变化，返回按范围分开的计算结果与证据，供分析 Agent 检验解释并形成发现。

适用：活动变化、参与地址、转账结构及必要的比较或背景研究；具体指标只能使用已实现并验证的口径。
不适用：单凭 Transfer 直接解释价格下跌、把铸造当买入、把转账当卖出、推断没有证据支持的因果，或默认扫描全部历史。

参数语义：chain_id、token_address、periods.focus_period 执行前必须明确。comparison_periods 和 context_periods 由问题和分析方法决定，记录选择理由；不全局强制填写。exclude_addresses 为明确研究条件中的排除项。模型不能通过参数指定身份、授权、SQL 或任意代码。
参数类型与组合规则由 Pydantic 模型定义。时间采用带时区的左闭右开区间；用户明确历史范围不额外减三小时。执行截止来自现有采集完成记录，范围不足交回主 Agent 调整，不静默裁剪。

结果使用：结合重点、比较和必要背景回答用户问题，不将聚合数字本身当作研究结论。区分交易数、日志数、普通转账、铸造与销毁；实际口径随方法版本返回。金额使用最小单位字符串及明确精度。提出“为什么下跌”的解释还需相应价格、交易等证据，说明已有依据与缺少的支撑即可，不编造概率。
状态处理：partial 保留限制；失败、取消和不支持不能伪装成成功空数据。主 Agent 可根据结果选择进一步工具或追问，不固定所有用户的分析路径。

已实现口径：各时段分别计算 Transfer 日志、不同交易、活跃收发及去重地址、普通转账/铸造/销毁/自转账/零地址互转分类、零金额日志与精确金额；零地址不算活跃参与地址。按普通转账金额列出发送/接收地址贡献。重点与比较范围返回精确差值，仅等长正基准给相对变化分数；背景范围保留自身指标。证据引用只是头部样例，排名和总量使用本次预算内全部正式事件。不能把转账总额称为 DEX 成交量、将地址数称为人数。超行数预算不输出截断后的完整合计。

示例意图：“所选时段 BEM 活动有什么变化，哪些现象值得继续调查？”——按问题选择比较和背景，返回可核查的指标，再由分析 Agent 形成发现与待检验解释。
