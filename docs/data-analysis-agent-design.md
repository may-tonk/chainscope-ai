## 1. 目标与现有基础

采用“主 Agent 动态调度三个专业 subagent，分析工具负责可信计算，研究过程允许补查与异步执行”的结构。用户问题决定分析路径；系统预先定义数据合同、计算方法、证据要求和执行边界。

模块的任务是：将用户问题转成可执行研究，通过适用方法获取证据，判断证据支持什么结论，必要时继续调查，交付可追溯、可继续追问的回答或报告。

同时服务普通持币者与链上研究者，根据问题调整解释深度，不要求用户先选择身份或分析模板，不限制用户只能提出预设问题。

## 2. 总体运行与反馈

正常研究的逻辑关系：

用户 → 主 Agent → 信息提取 → 程序校验 → 数据分析任务 → 结果校验 → 总结 → 主 Agent 复核 → 用户。

这不是强制单向流水线：

- 请求不明确时返回主 Agent，进行必要澄清。
- 证据不足或相互矛盾时返回数据分析 subagent 补查。
- 数据或能力不支持时，明确返回限制和已经能够回答的部分。
- 简单问题可以复用已有请求或结果，不必完整重跑三个模型。

主 Agent 始终维护会话与研究任务的关系。子代理不创建不受控的代理网络，不绕过主 Agent 修改用户研究目标。

三个 subagent 是三种职责；一次研究可以启动多个数据分析任务实例。

## 3. 角色职责

| 角色 | 输入 | 工作 | 输出 |
| --- | --- | --- | --- |
| 信息提取 subagent | 当前问题、必要历史、已有报告上下文 | 识别对象、目标、范围、比较条件、约束与歧义 | ResearchRequest |
| 数据分析 subagent | 校验后的请求、能力目录、数据上下文 | 检查覆盖、制定步骤、选择方法、调用工具、核验与补查 | AnalysisResult |
| 总结 subagent | 原始目标、校验结果、证据与限制 | 组织回答、图表说明与报告草稿 | AnswerDraft |
| 主 Agent | 用户对话、任务状态与结果 | 调度、澄清、处理变化、复核、最终交付 | 回答及报告入口 |

信息提取不提前写死分析方法；分析 Agent 应解释方法适用性与证据缺口；总结不新增无来源的数值、身份判断或因果解释。主 Agent 复核失败时退回对应环节，不仅重新润色。

模型通过统一工厂配置，任务保留模型、提示词和方法版本。

## 4. 结构化合同

### 4.1 ResearchRequest：研究请求

| 字段组 | 内容 |
| --- | --- |
| 标识 | 请求编号、研究编号、请求修订号、schema 版本 |
| 目标 | 用户原问题、整理后的研究目标 |
| 对象 | 链、代币合约、地址、池子 |
| 范围 | 时间、时区、区块条件、比较范围 |
| 约束 | 用户要求排除或重点关注的内容 |
| 上下文 | 报告及版本、既有结果引用 |
| 参数依据 | 用户提供、历史继承、元数据核实或系统假设 |
| 未决事项 | 缺失信息、歧义及是否影响执行 |

要求：

- 自由表达问题，结构化执行信息，不枚举所有允许提问的句子。
- 明确“最近”的参考时刻；数据滞后时不能静默把研究终点改成库中最新时间。
- 未知字段允许为空或待澄清，不能为了通过 schema 编造。
- 只对明显影响回答的歧义要求用户澄清；其他合理假设须披露。
- 用户身份、资源权限与预算由后端可信上下文注入，不由模型指定。
- 合约与精度通过可信元数据核实，不凭模型记忆填写。

### 4.2 AnalysisResult：分析结果与证据

保存：

- 完成、部分完成、数据不足、能力不支持或失败等结果状态。
- 实际范围、数据快照、覆盖状态。
- 分析步骤、方法与版本。
- 精确结果和图表数据引用。
- 发现及支撑证据。
- 待验证假设、替代解释、数据限制。
- 核验项目和结果。
- 如需补查，明确缺少的证据。

发现必须能连接到计算结果、方法、数据范围与可下钻记录，不能只返回“分析完成”的自然语言。大结果通过分页和结果引用访问，不能将全部事件塞入模型上下文，截断也必须明确说明。

### 4.3 AnswerDraft：总结草稿

包含直接回答、关键发现与证据编号、图表引用、限制、未解决问题、继续追问方向和结果版本。优先引用已计算数值，不由总结模型自行重新计算金额或比例。

### 4.4 校验

使用 Pydantic 等程序校验字段、类型、时间逻辑、对象有效性、证据引用与版本关系。格式合法不代表事实正确，仍需业务与计算校验。

DeepSeek 的结构化输出策略通过实际兼容测试确定，不因框架提供能力而假定模型调用链有严格保证。

异步执行另有任务合同，见第 7 节。详细字段、类型和错误枚举在实现前审阅。

## 5. 工具与分析方法

计算能力与分析方法知识分开维护：工具执行可靠操作，skill 说明某类研究的方法和判断依据，MCP 连接外部能力。

| 能力组 | 操作 | 边界 |
| --- | --- | --- |
| 对象与覆盖 | 元数据、Transfer/Swap/持仓覆盖 | 有记录不代表范围完整 |
| 转账与交易证据 | 地址明细、事件、同交易事件关系 | Transfer 不直接等于买卖 |
| 行为分类 | 零地址、自转账、池子交互、可识别路由及流动性 | 未确认情况保留未知 |
| 时段与分组比较 | 趋势、构成、增量贡献、分组比较 | 范围和分母必须可比 |
| 持仓与分布 | 快照排行、集中度、变化 | 依赖完整历史、余额规则和快照 |
| 路径与关联 | 转账路径、同交易与跨时间关系 | 时间先后不证明资金来源或共同控制 |
| 机制检索 | 合约、文档、已核验研究材料 | 文档陈述与链上事实分开 |

以上是能力分类，不表示已经全部可用，不要求做成万能工具，也不要求每个统计字段各建一个工具。工具粒度以准确选择、清晰输入和能支持后续调查为标准。

分析方法说明：适用问题、所需数据、检查步骤、常见误判、结论边界和可用工具。动态选择方法与顺序，不将研究固定成单一模板。

MCP、网页、合约文本和检索结果仅作为数据材料，不能改变系统权限或执行规则。

缺少能力时明确返回缺口，不开放任意 SQL 或任意 Python；新方法实现、验证后加入能力目录。

## 6. 数据分类与计算原则

1. 原始事实只读，派生结果不覆盖事件，研究账号与写入职责分离。
2. 只统计请求范围内的正式数据，暂存、失败与覆盖不足不能当成完整结果。
3. 金额采用整数与十进制字符串，精度来自元数据；不用 float 准确核验，不默认 18 位。
4. 事件、交易、地址与实体分开。地址数不是人数，日志数不是交易数。
5. 支持多维行为标记。同交易可以同时发生领取、转账、卖出及流动性行为。
6. 分类保留依据和版本；发起人、接收方、多池合并与未知情况可回查。
7. 每日独立地址数不能相加得到多日独立地址数。
8. 异常检测说明基准与方法；异常不直接等于操纵或恶意行为。
9. 增量贡献不等于因果证明，动机和实体归属需要额外证据。
10. 零地址发出单独统计；dead 地址转入不能自动认定 totalSupply 减少。

持仓新增独立只读路径，不直接调用默认刷新写库的 CLI。其他复用入口也检查副作用，采集代码保持原样。

## 7. 异步任务与恢复

建议 LangGraph 管理研究状态和分支，后台任务系统管理执行、重试和恢复。现有 Celery、Redis 客户端进入适配验证，不重新安装整套环境。

建议状态：`queued → running → succeeded / partial / failed / cancelled`；需补充时为 `needs_input`。重试保存为执行尝试，不覆盖失败证据。取消请求与最终取消确认应区分，具体状态机另行审查。

任务保留：用户、会话、研究、请求修订号；子目标、输入与依赖；快照与方法版本；尝试、心跳、超时和取消；结果、错误和资源消耗。

执行规则：

- 独立分支并行，有依赖的等待。
- 分支尽量共同绑定截止区块；其他来源明确各自快照。
- 用户改条件产生请求修订，旧结果不能覆盖新请求。
- 取消在安全边界生效，不承诺撤回已发出的请求。
- 只重试适合重试的故障，不盲目重试冲突或权限拒绝。
- 按可能重复投递设计，使用幂等键、租约和发布去重。
- 持久提交结果后再发布完成事件，避免通知成功但结果丢失。
- 后台期间主 Agent 保持对话能力；关键分支未完成不能宣称研究全部完成。

并发、查询时长、模型调用次数和费用上限由服务端控制，具体值通过代表性任务实测，不虚构上线容量。已确认的熔断、停止和失败传播原则见第 13～16 节，具体实现与参数仍需审阅。

## 8. 存储、缓存与报告

| 存储 | 建议职责 |
| --- | --- |
| MySQL | 原始链上事实、既有采集与覆盖 |
| 独立 PostgreSQL 研究库 | 研究请求、任务、分析结果、证据索引、报告版本与必要派生结果 |
| LangGraph checkpoint | 图执行状态，独立命名空间 |
| Redis 6379 | 可重算的结果缓存 |
| Redis 6380 | 队列、协调锁和并发控制 |

独立 PostgreSQL 研究库仍是建议，尚未创建。研究迁移单独管理，不进入账户或现有 MySQL 迁移链，不复制整份链上事实库。

频繁昂贵计算采用版本化预聚合或保存结果，加速不能改变指标含义。历史修正触发相关派生结果失效或重算。

缓存标识包含能力、参数、分类/方法版本、快照和数据修订；私人结果按权限隔离，命中缓存仍校验访问权。截止区块不变不代表历史结果未改变。

报告保留问题、证据、图表、口径与版本。追问沿用原快照或显式更新，更新产生新版本，不静默改旧报告。

网站保留独立“AI 研究”和“我的报告”。认证后经网站服务调用研究包，不反向依赖网站路由。

## 9. 上线验收

| 项目 | 必须达到的结果 |
| --- | --- |
| 问题理解 | 对象、范围和条件正确，关键歧义不擅自补齐 |
| 工具选择 | 方法适用，缺少能力明确说明 |

| 总结 | 数字和结论可追溯，不新增无依据说法 |
| 分支一致性 | 快照、修订和依赖正确 |
| 恢复 | 中断、重启、重复投递、取消、超时有明确处理 |
| 用户隔离 | 不得访问他人的任务、报告、证据或缓存 |

## 13. 已确认原则：用户与工具授权

确认依据：2026-11-09 用户反馈“这部分没有太大的问题，可以写入我们的 .md 文档里面”。本节至第 16 节记录此前讨论的原则，不代表相关代码已经实现；具体中间件划分和参数未因此定稿。

### 13.1 可信用户身份与访问控制

- `user_id` 来自网站后端已经验证的会话，前端和模型不能指定自己的身份。
- 身份之外，检查账户可用性、能力权限、资源归属、数据范围和资源预算。拥有研究权限不代表可以读取他人报告或启动采集。
- 主 Agent、三个 subagent 和工具均使用服务端注入的可信上下文，不能自行扩大权限。
- 异步任务保存可信归属，worker 执行前重新检查；每次工具调用、证据读取、缓存返回、报告读取与导出都校验权限。
- 无法确认授权时拒绝操作，不以缓存或过往授权绕过检查。
- 网站用户不持有数据库凭证；受限服务账号的数据库权限与网站用户的业务授权分别实施。
- 原始事实访问只读。任务、报告等写入仅经受控业务服务执行，不把迁移权限交给模型。

### 13.2 工具放行条件

有效权限取以下条件的交集：用户能力权限、当前子代理职责、任务对象与范围、资源归属以及执行预算。模型提出调用，程序决定是否执行。

| 角色 | 允许的职责范围 | 限制 |
| --- | --- | --- |
| 信息提取 | 元数据解析、必要且已授权的历史与报告上下文 | 不执行大范围分析、不修改权限 |
| 数据分析 | 已授权的只读分析、证据查询与指定检索 | 不写原始事实，不执行任意 SQL、shell 或代码 |
| 总结 | 当前任务已授权的结果、证据与方法说明 | 不擅自扩大研究或重新采集 |
| 主 Agent | 调度、状态读取、补查与交付 | 不绕过下层授权 |

Skill 不授予权限；MCP 工具进入同样的授权流程。仅从模型可见清单隐藏工具不能替代执行校验。

工具登记包含用途、输入输出 schema、所需权限、读写性质、范围、超时、成本限制、重试条件、幂等要求和取消方式。

## 14. 已确认原则：异常边界与失败传播

### 14.1 分层处理

| 层次 | 职责 |
| --- | --- |
| HTTP 接口 | 请求编号、会话接入、统一安全错误响应与脱敏日志 |
| Agent 执行 | 模型与工具调用检查、预算、循环限制 |
| 服务及数据访问 | 不可绕过的授权、归属和业务参数校验 |
| 后台任务 | 持久状态、执行尝试、心跳、超时、取消与恢复 |
| 外部连接 | 网络超时、连接释放、有限重试与依赖熔断 |

不能依赖一个全局 catch，也不能仅依赖 HTTP 检查。HTTP 中间件不能捕获另一 worker 的异常；服务层授权覆盖内部调用、后台任务与 MCP 路径。

流式响应开始后，通过明确的错误或终态事件通知客户端，并更新持久任务状态；不能假设仍可改写成普通 HTTP 错误响应。

### 14.2 按影响范围处理

| 情况 | 处理 |
| --- | --- |
| 请求存在关键歧义 | 停止依赖这些参数的分析，交主 Agent 澄清 |
| 模型输出不符合 schema | 预算内有限修正，仍失败则停止该步骤及依赖分支 |
| 临时网络或服务错误 | 有限重试，耗尽后按依赖处理 |
| 可选检索、辅助图表失败 | 独立分支继续，披露缺失 |
| 核心查询失败 | 停止依赖分析，不能输出对应结论 |
| 金额冲突、快照不一致、对账失败 | 阻止受影响结果进入总结，保留证据调查 |
| 失去本次研究执行权限 | 停止后续受保护调用和交付，请求停止研究 |
| 总结失败 | 保留已核验分析结果，有限重试，不能抹除已完成工作 |
| 未知程序异常 | 停止受影响任务，记录脱敏诊断，不能返回空结果冒充成功 |

业务异常默认不关闭整个网站或 worker。执行前在研究计划中标明回答所需的必需依赖与补充依赖；不能在失败后为了宣称完成，把必需项改成可选项。计划确需变更时记录修订及其对回答范围的影响。

允许返回已核验的部分事实，但关键问题未被回答时，不标为完整成功。主 Agent 可决定补查，不能绕过程序校验发布不可信结论。

### 14.3 统一错误合同

错误合同包含稳定的 `code`、安全 `message`、`request_id`、`task_id`、影响范围 `scope`、`retryable`、可选 `retry_after`、结果状态与 `next_action`。

数据库原始错误、堆栈、凭证及内部连接信息不发送给用户或模型；内部诊断受限且脱敏。失败不能转换为零、空数组或“未发现”。

## 15. 已确认原则：重试与熔断

### 15.1 重试

- 网络波动、适合恢复的服务端错误采用有限重试、指数退避和随机间隔。
- 限流尊重服务端等待提示，并检查当前任务与用户预算。
- 权限拒绝、非法参数、确定性数据冲突不自动重试；模型参数错误只允许有限修正。
- 写入或外部副作用的结果不明时，先检查幂等记录，不盲目重放。
- 客户端、工具、图节点与队列共用可核算的重试预算；不能每层各自无限或叠乘重试。
- 持久任务、幂等、任务确认和恢复检查配合使用，不承诺仅配置队列就能保证恰好执行一次。

### 15.2 熔断

正常 → 持续故障达到条件 → 暂时拒绝新调用 → 冷却后少量探测 → 恢复或继续熔断。

- 按依赖和能力隔离；模型、行情、MCP 等故障分别判断，必要时区分凭证范围。
- 参数错误、权限拒绝和个人额度不足不计入共享依赖故障，不误伤其他用户。
- 熔断返回依赖暂不可用，不伪装为无数据。
- 不依赖故障服务的分支可以继续；依赖它的核心结论停止。
- 不自动切换模型、数据源或统计口径。替代路径需验证，且披露变化。
- 触发条件、窗口、冷却和探测配置需根据代表性任务实测，尚未确定数值。

## 16. 已确认原则：停止与权限变化

### 16.1 协作式取消

1. 持久保存取消请求，停止派发新子任务。
2. 运行任务在安全检查点退出，清理连接与锁，保存已完成结果。
3. 确认活动执行结束后标记最终取消，区分“已请求停止”与“已经停止”。

取消 Python 等待不保证数据库 SQL 已停止；数据库端查询超时与连接清理需单独实现。强杀不是常规停止方式，仅作为受控的最后手段；不强杀整个网站服务。

### 16.2 不同事件的行为

| 事件 | 行为 |
| --- | --- |
| 页面关闭或浏览器断开 | 已接受后台任务继续，之后重新查看 |
| 正常退出或会话过期 | 不自动取消已接受研究，查看时重新认证 |
| 账户禁用或研究权限撤销 | 阻止后续受保护调用和交付，请求停止相关任务 |
| 用户明确停止 | 执行协作式取消 |
| 账户注销 | 与删除策略联动，停止任务并防止晚到结果恢复已删除私人资源 |

后台任务基于持久的用户与任务授权重新校验，不依赖浏览器 Cookie 长期有效。已发送的外部请求不承诺可撤回；晚到结果在提交和发布前重新检查取消、请求修订及授权状态。

## 18. 已确认要求：异步中间件与框架组件复用

用户要求面向多用户使用，研究中间件采用异步设计。五类职责为 RunGuardMiddleware、ToolPolicyMiddleware、ModelCallMiddleware、ToolExecutionMiddleware、TraceMiddleware；这是设计名称，尚未创建业务文件。

- 研究执行入口采用异步调用或流式调用，模型与工具包装实现异步接口；启动检查和测试应发现仅有同步实现导致的异步保护缺失。
- 异步链中的网络、Redis、数据库和持久化不能用阻塞调用占住事件循环。既有同步驱动需在受限线程池或 worker 中隔离；CPU 密集分析进入受控计算执行资源，不能仅把函数改成 async 就视为解决并发。
- 异步不自动保证用户隔离。用户、会话、研究、任务和尝试分别标识；请求上下文不存入可变全局变量；多 worker 共享授权、预算、限流与协调状态。
- 主 Agent 与所有子任务受同一研究预算控制，并发预留和结算必须原子化；任务取消传播不能当作普通可重试异常吞掉。
- 日志、清理和状态持久化也需保证取消与异常路径可执行，不能依赖正常返回钩子完成所有收尾。

允许合理复用 LangChain/LangGraph 已有能力，但不是必须使用，也不能因“框架内置”跳过业务授权和验收。LangChain middleware 与 LangGraph 状态、checkpoint、重试等图能力分别说明，不混称为同一种中间件。

决定采用具体内置组件前，向用户说明名称、职责、锁定版本的兼容性与异步支持、配置、状态作用范围、多用户/多 worker 行为、局限、与自定义逻辑是否重叠，以及验证方式。不得静默引入组件或叠加重试、计数和预算策略。本次未选定或启用新的内置组件。

参数传输与返回 schema 的已讨论设计原则见第 19 节；时间交互采用第 20 节的最新约定。核心合同实施情况见第 22 节，中间件执行尚未接入。

## 19. 参数传输与返回 schema 设计原则

### 19.1 字段来源

| 内容 | 生成与控制方 |
| --- | --- |
| 用户身份、实际权限、执行预算 | 后端认证与授权服务注入，模型不能修改 |
| 会话、研究、任务、调用和结果编号 | 后端程序生成与关联 |
| 研究目标、对象、条件和歧义 | 信息提取 subagent 根据对话提取 |
| 分析步骤、方法、补查建议 | 数据分析 subagent 提出，按既有执行规则放行 |
| 数据截止、实际计算结果和执行状态 | 现有采集记录、数据服务与执行程序提供 |
| 发现、解释与总结草稿 | 相应 subagent 生成并引用证据 |

模型传业务内容，程序附加可信身份和执行信息；不要求模型生成 user_id 或执行权限。各传输边界使用独立的小合同，不采用一个包含所有信息的大 JSON。

### 19.2 信息提取到分析：ResearchRequest

字段包括 `schema_version`、`goal`、`targets`、`periods`、类型明确的 `constraints`、`context_refs`、`assumptions`、`unresolved` 和 `readiness`。时间字段按第 20 节区分重点、比较和背景范围；具体操作是否要求时间、代币、地址或哈希，按第 21 节及对应工具 schema 判断，不将全部字段设为全局必填。

`readiness` 表示研究意图是否足够明确，不由模型保证数据已经存在。参数保存来源依据，例如用户消息、历史继承或报告版本。信息提取不提前指定全部分析方法。

### 19.3 分析到工具：调用参数与计划

- 调用编号、可信上下文、任务修订、截止期限和数据快照由程序控制。
- 模型按工具独立 schema 提交对象、范围、分组、方法参数和筛选条件。
- 用户已确认：参数根据工具任务类型选择，由对应工具 schema 声明必填、可选、条件必填与字段组合规则。调用前只要求当前操作所需信息明确，不因其他尚未执行工具缺少参数而阻塞所有可独立进行的工作。
- 统一分析入口如采用能力名称加参数，也必须按已登记能力的具体 schema 解析，不接受任意 dict、SQL 或代码。
- 分析计划记录子任务目标、依赖、必需性、方法选择原因、预期证据和补查条件；允许动态修订并保留记录。

### 19.4 工具返回：ToolResult

按 `success`、`partial`、`needs_input`、`unsupported`、`failed`、`cancelled` 区分结构。

- 成功结果携带计算结果、实际范围、数据截止、方法版本和证据引用。
- 部分结果说明缺失与限制；失败使用安全错误合同；取消不能冒充空结果。
- 完整可用范围内没有事件是成功的零结果，查询失败不是零结果。
- 返回金额单位、代币精度、分页、截断、样本说明与结果引用。
- 大结果保存在存储，通过引用或分页获取，不把全部原始事件送入模型。

### 19.5 分析到总结：AnalysisResult

分开保存 `findings`（证据支持的发现）、`hypotheses`（待检验解释）、`limitations`、`checks`、`followups` 和 `result_refs`。

每项发现有编号、陈述、支撑结果/证据、适用范围和必要限制。面向用户简要说明判断依据及缺少的材料，详细方法保留在报告和证据记录中，不堆叠保守措辞。没有计算依据时不任意生成概率数字；统计区间须来自明确方法。

### 19.6 总结到主 Agent：AnswerDraft

返回直接回答、结论与证据编号、图表/报告结构、必要限制、未回答事项和分析结果版本。主 Agent 可交付、要求补查、更正表达、澄清或说明无法完成；总结不改金额、数据截止和任务终态。

### 19.7 异步传输与通用格式

- `request_revision` 标识条件变化，`task_id` 标识逻辑任务，`attempt_id` 标识执行尝试，`call_id` 标识调用，`result_id` 标识保存结果。
- 事件包含事件编号、任务与研究编号、请求修订、类型、时间、顺序信息及类型化内容或结果引用。
- 队列尽量只传任务编号，由 worker 获取可信任务记录，不传浏览器 Cookie、数据库密码或整段私人对话。
- 时间带时区，区间统一为左闭右开；金额和超出安全整数范围的值使用十进制字符串。
- 未知、零值和不适用分开；字段类型、允许字段、引用归属与版本采用程序校验。
- 这些是接口与安全合同要求，不因此另加采集完整性验收或延迟验证工作。

## 20. 时间追问与分析范围

### 20.1 数据结束时间：采用现有采集记录

按用户最新澄清，分析可用的最新结束时间直接采用数据库现有记录中已完成采集的数据截止时间。当前约三小时延迟属于运行背景，不将“当前时间减三小时”另设为时间计算或核验规则。

不为确定这个时间新增链头探测、重新采集、回执核验、跨源对账或其他验收流程。沿用项目已有采集进度，不用最后一条事件的发生时间猜测无事件区间是否完成。

用户选择“最近 N 小时/天”时，以该数据截止时间为结束，向前取 N 个小时/天；页面明确显示实际起止时间和数据截至时间。一次研究固定该范围，异步执行和重试不随时钟移动。

明确指定的历史范围保持用户原意，不统一再减三小时。用户要求超出现有数据截止时，直接说明当前可用截止并让用户调整，不静默裁剪或承诺分析尚未采集的数据。

### 20.2 主 Agent 发起简短追问

- 时间缺失且影响回答时，由主 Agent 弹出小对话框。
- 支持最近多少小时/天、指定起止时间、沿用已有图表或报告范围，显示时区和现有数据截止时间。
- 用户已明确范围时直接采用，不重复追问。
- “最近”不静默固定为七天；取得用户的时间参数后恢复原研究。

追问保存 `clarification_id`、所属研究及请求修订。等待输入时为 `needs_input`，不占住数据库连接或计算资源；提交时执行既有身份、资源归属与参数校验，旧弹窗不能覆盖新请求。

### 20.3 重点、比较与背景范围

| 字段 | 用途 | 选择方 |
| --- | --- | --- |
| `focus_period` | 用户希望解释的时段 | 用户确定 |
| `comparison_periods` | 判断变化程度、提供比较基准 | 分析 Agent 按问题选择 |
| `context_periods` | 趋势、发行、持仓等相关背景 | 分析 Agent 按研究需要选择，并记录理由 |

最终回答围绕重点范围，结合相关比较和背景说明原因；不是只分析重点时段内的孤立事件，也不默认扫描全部历史、所有地址和全部指标。

正常权限与预算内的必要背景分析自动执行，界面简要披露采用范围。扩展记录理由、所需数据和待检验解释；明显改变研究目标、越过用户约束或预算时交主 Agent 处理。所需链上数据的结束时间遵守现有采集截止。

### 20.4 时间相关字段与表达

保留 `time_expression`（用户原话）、`resolution_source`（明确指定、上下文或澄清等）、`reference_time`（解析参考时刻）、范围字段、`requires_clarification`、`range_note`、`analysis_as_of`（分析采用的资料时点）以及来自现有记录的 `data_cutoff_time`。

程序固定具体时间，模型不能编造数据截止。请求条件变化创建新修订，复用仍适用结果，重算受影响部分。

对“为什么下跌”等问题，采用可用价格来源核实用户所指现象，必要时澄清池子或计价单位；不凭 Transfer 直接推断价格变化。回答简述事实、判断依据与缺少的支撑材料，不将相关性自动写成已证实因果。

## 21. 已确认要求：按工具任务类型选择参数

用户确认参数必填规则按具体 tool 的任务类型确定。应区分“用户必须提供的信息”和“程序执行当前操作前必须明确的信息”；后者可以来自当前输入、历史上下文、已授权报告或现有数据库记录，不要求用户一次填完所有字段。

### 21.1 必填、可选与条件必填

| 参数 | 规则 | 来源与用途 |
| --- | --- | --- |
| 用户输入 | 必需 | 问题、哈希或对既有结果的追问均可构成输入 |
| 研究目标 | 执行研究前明确 | 信息提取整理；歧义影响操作时主 Agent 追问 |
| 研究对象 | 对应链上分析执行前明确 | 可以为代币、地址、交易、区块或多个对象 |
| chain_id | 链上查询前明确 | 可继承已明确的 BSC 上下文，无依据时不猜测或全链搜索 |
| 代币合约 | 代币范围任务条件必填 | 代币活动、持仓等分析需要；交易解析不要求用户另填代币 |
| 地址 | 地址范围任务条件必填 | 定位所研究地址；其他任务不强制填写 |
| tx_hash | 指定交易任务条件必填 | 定位交易；支持按任务需要接收多笔交易对象 |
| block_hash | 指定区块哈希任务条件必填 | 定位区块；不强制所有研究填写 |
| 时间 | 时段任务条件必填 | 统计、趋势和变化分析需要，单笔交易解析通常无需用户另填 |
| 比较范围 | 使用比较方法时明确 | 用户指定或分析 Agent 选择并说明 |
| 背景范围 | 按问题与方法需要 | 由 Agent 选择，遵守权限、预算及用户约束 |
| 筛选、排除、关注条件 | 用户可选 | 明确指定后必须遵守，不自动丢弃 |
| 报告或研究引用 | 基于相关资源追问时明确 | 检查归属并绑定版本 |
| 展示偏好 | 可选 | 例如图表或表格，不作为数据查询身份与权限 |

代币、地址、交易和区块参数不同时全局必填。可选的是用户是否指定比较或背景；当分析方法需要时，执行仍需形成对应参数。没有具体分析对象的一般知识问题由主 Agent 按能力处理，不强制进入链上查询工具。

### 21.2 哈希对象

| kind | 执行前必要字段 | 可选补充 |
| --- | --- | --- |
| token | chain_id、address | 任务要求的范围或条件 |
| address | chain_id、address | 关注代币、时间和行为 |
| transaction | chain_id、tx_hash | 关注代币/地址、日志位置、前后观察范围 |
| block | chain_id、block_hash | 关注代币、地址和事件类别 |

哈希不能塞进含义不明的地址字段。交易哈希与区块哈希形状相近，不仅凭长度认定；依据用户语义和上下文判断，不能明确时追问。多个对象各保留自己的链和类型。

用户仅贴哈希也是有效输入；缺少研究目标时结合上下文或澄清，不编造意图。单笔交易定位后读取已有区块与时间，不强制弹出时间框；调查交易前后行为时，再按任务需要确定观察范围。

同一交易内的多条日志不能作为多笔独立交易统计。分析可梳理已有事件的顺序、参与对象与可识别行为，但库中存在 BEM 相关事件不代表已掌握完整交易的所有代币、调用和日志。输出说明解析范围，缺少数据不宣称完整解析。

当前库未找到时返回“当前数据中未找到”，不能直接认定链上交易不存在或执行失败，也不因此自动重采。证据引用保留链、交易哈希及需要时的日志序号。

### 21.3 时间参数组合

- 相对时间：需要正时长与小时/天单位，结束取现有已完成采集数据截止时间。
- 指定时段：执行前明确起止边界与时区，允许从用户表达和上下文解析。
- 单笔交易：对象明确后使用交易所属时间，不强制提供独立起止参数。
- 交易前后调查：按研究目标确定前后观察范围及截止，必要时澄清。
- 时区必须明确，可以采用界面展示的北京时间，不要求用户重复选择。

### 21.4 系统必需信息与执行准备

可信 user_id、账户及权限、会话与研究编号、请求修订、执行尝试与调用编号、适用的数据截止/快照、期限与预算由服务端按生命周期提供，不属于模型或用户表单可随意填写的参数。

## 27. 四类数据工具执行交付：2026-11-10，待用户检查

本节记录实际新增能力；第 22～26 节是各次交付时的历史状态，不能再用其中“工具未实现”描述当前执行层。用户本次授权完成四个工具，未授权同时扩展记忆、RAG、网站研究 API 或全部 subagent。

### 27.1 执行路径与能力

执行路径为：Pydantic 工具参数＋服务端 ExecutionContext → 当前用户/工具/数据集授权 → 有界线程中的 MySQL 只读快照 → 正式事件选择 → 分类与整数计算 → 查询后重新授权 → 类型化结果。LangChain `StructuredTool` 的 coroutine 调用这一真实路径，不是模拟返回；JSON Schema 始终从原 Pydantic 输入模型生成，再以 JSON 校验兼容日期字符串和数组。模型不能传入 user_id、SQL、权限或截止覆盖值。

| 工具 | 已执行内容 | 仍有的业务边界 |
| --- | --- | --- |
| lookup_transaction_events | 交易哈希定位；正式 Transfer＋已补齐 Swap 明细、引用和签名续页 | 已授权代币数据集，不是全链交易回执、调用树或未采集资产追踪 |
| lookup_block_events | 缓存区块哈希或已有 Transfer 定位区块；分页返回上述事件 | 不代表全区块全部交易，缓存与 Transfer 均缺失时不能断言区块不存在 |
| analyze_address_activity | 指定代币的重点/比较/背景时段；活动计数、分类金额、普通转账收发净流、对手贡献及变化 | 净转账流不是余额、持仓、利润或实际买卖 |
| analyze_token_activity | 各时段的日志/不同交易/活跃地址、分类计数及金额、发送接收贡献、重点与比较差值 | 不是 DEX 成交量、价格归因或全量持币者分析 |

比较与背景由上层按用户问题传入，不写死研究步骤。背景保留自身结果，比较才生成对重点的差值。相对变化采用精确分数，仅等长区间、正基准且非地址净流时给出；零基准和不等长范围不制造增长率。事实观察、来源、方法版本和局限供后续分析 subagent 检验解释；四个工具本身不替代专业分析 Agent。

### 27.2 清洗与指标口径

- 仅纳入当前数据集正式 done 窗口及连续完成水位内事件，EXISTS 防止关联重复放大。同一交易多日志只算一笔交易，不把日志数称为交易数。
- 单条金额必须为规范 uint256 十进制原值，合计使用 Python int、输出字符串，允许合计超过 78 位。非法原值或精度冲突明确失败，不丢行、不补零。
- Transfer 互斥分为普通、零地址发行模式、零地址销毁模式、自转账、零地址互转。零地址互转独立统计；dead 地址不自动算销毁；零金额保留真实日志。该分类不证明 totalSupply 的真实变动。
- 地址净转账流仅是普通转账流入减流出；发行、销毁、自转账另列。活跃地址排除零地址，也不当成真实人数或持币者数。
- 各区间采用 [start,end)，排除任一端命中 exclude_addresses 的事件。证据默认只取前 10 条，显式标记采样；总量、贡献排名基于该次预算内全部事件，不从证据样例推算。

### 27.3 授权、异步与失败边界

`contracts/access.py` 定义异步 ToolAuthorizer 端口，按可信 user_id 返回允许的工具及 job_id。真实网站权限源必须由后续网站集成注入；没有默认允许器。本地只读验收命令显式限制一个操作者身份和一项任务，不等于网站鉴权完成。查询前后均重新授权；禁用工具既不暴露，也不能直接执行。

`config/research_tools.yaml` 是运行策略值的来源：每实例并行 2、每时段最多 200000 条正式 Transfer、总时段最多 12、证据 10、各方向地址贡献 5、查询工具 20 秒/活动工具 30 秒。值经 `core/tool_settings.py` 加载并用于执行，修改后重新装配生效；输入/输出 Schema 仍在 contracts，不在 YAML 手写另一套类型。

异步服务使用有界线程执行同步驱动与精确计算。等待超时通知线程协作停止，SQL 有服务端执行时限与驱动读取超时，但不宣称已强制杀死 SQL；资源待线程真实退出才归还。上层协程取消继续传播。当前没有数据库自动重试、熔断状态机、持久暂停恢复或跨 worker 预算。结果独立交给编排方决定后续分支，不能依据失败结果继续形成结论。

失败不会变成空数组成功；超范围或无唯一数据集为 unsupported；超预算/数据库故障/非法参数/无权限为 failed；查询目标可能受 Swap 独立补采缺口影响时为 partial 并附局限，已在补采水位以内的旧交易不因此误报；真实未匹配事件才返回成功空页。签名游标绑定用户、研究修订、过滤与已有快照，变更或过期须重新查询，不用 OFFSET。签名密钥须显式注入，网站部署需跨实例共用受保护密钥。
