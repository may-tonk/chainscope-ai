## 数据与运行身份

同一交易可以产生多条 Transfer，事件身份包含链、交易哈希和日志序号。重复采集复用相同事件，保留对应执行与关联记录。

`run_id` 定位逻辑运行，`attempt_id` 区分执行尝试，`event_id` 定位一次结束结果。时间用于查询、排序和解释，不作为唯一编号。数据库时间列按 UTC 保存，对话展示用北京时间。

Agent 最终状态与结束快照在同一事务保存，报告正文在 `agent_events.payload.report`。采集状态和报告状态不同；`displayed` 表示程序完成显示调用并记账，不代表操作者已阅读。任务总条数与本运行新增条数分别报告；当前未精确统计本运行新增 Swap，不能填零。

## 归档与清理

默认采集不按事件生成 JSON。显式调试归档单批默认 10 MiB、整个 `raw` 内容最多 100 MiB，旧文件也计入。新调试批次不生成 `events.json`，已有旧样本可能包含它。超限报错，没有自动清理、压缩或回放；原始响应不是数据库备份。

数据库可能保存 `raw_directory`，报告也可能引用日志、归档或备份。清理前核对引用与活动进程，有引用的文件保留路径。本机部分历史原路径已失效，在外部归档区找到了同编号目录；这影响历史证据追溯，本轮清理没有移动归档或改写数据库记录。

可再生成的缓存、空占位文件和确认重复的旧副本与业务证据分别处理。虚拟环境、当前安装元信息、本地配置、样本和 SQL 备份不作为本轮清理目标。

## JSON Schema

源定义在 `python/chainscope/agent_contracts.py`，`agent_tools.py` 通过 `model_json_schema()` 生成工具参数 Schema。输入输出还在本地验证，权限、预算和目标一致性由程序检查。

当前没有手工维护的独立 `.schema.json`。如需共享可从同一份定义自动导出，避免两份规则不一致。`raw` 和 `reports` 的 JSON 是数据或结果，不是工具 Schema。
